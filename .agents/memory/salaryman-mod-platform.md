name: SALARYMAN community mods
description: Product intent and safety boundary for user-created SALARYMAN feature add-ons.
---

“Firmware” means installable game-feature add-ons, including 1999 presets and feature customizations, not physical-device firmware. Users may rewrite code for their own systems using a source fork. Keep community packages and source-code forks distinct: do not execute arbitrary uploads on shared SALARYMAN servers, and do not let client mods override server-owned multiplayer state.

The in-world modding entry points are computer/terminal and replicant-repair shops. Actual creator and player controls should be separate pages under browser Settings, not a new top-level app area.

The source repository is intended to remain open under GPL-3.0-only. Reuse of bundled art, audio, video, fonts, and other media still depends on each asset's license.

**Why:** The user wants community members to build on SALARYMAN and users to customize their own systems, while choosing an open-source license that remains stable and controlled.

**How to apply:** Use declarative packages for installable content, local forks for deeper code rewrites, and explicit server support for shared gameplay changes. Keep fictional shop interactions separate from browser account permissions and review workflows. Track media rights separately from source-code licensing.
